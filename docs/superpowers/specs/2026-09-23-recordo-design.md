# Recordo 設計

2026-09-23 の設計セッションで決めた内容。出発点は Notion の「Recordo / 壁当て」ページ。

## 目的

Claude Code で作業中に聞いた用語を、Claude Code 側の使い方を変えずに拾い、4択クイズにして忘却曲線に沿って復習させる macOS アプリ。数時間おきにアプリの方から出題する。

自分用。フルディスクアクセスの許可を作り直しても保つため、手元の開発用証明書（Apple Development）で署名する。見つからなければ ad-hoc 署名になり、作り直すたびに許可し直すことになる。公証、配布、App Store の準備はしない。

## 全体の構成

```
Recordo.app（メニューバーに常駐、Dock には出さない）
├ MenuBarExtra     今すぐ出題 / 今すぐ同期 / 最後に同期した時刻 / 設定 / 終了
├ QuizController   60秒ごとに起き、出題と1日1回の同期が要るかを判断する
├ QuizPanel        右下に出る4択の小窓。作業中のアプリからフォーカスを奪わない
├ Importer         history.jsonl → 判定 → 会話の切り出し → カード作成
├ ClaudeRunner     claude -p を子プロセスで呼ぶだけの部品。テストでは偽物に差し替える
└ CardStore        cards.json の読み書き
```

- SwiftPM で作る。ライブラリ `RecordoKit`、数行だけの実行ファイル `Recordo`、テスト `RecordoKitTests` の3ターゲット。Xcode のプロジェクトファイルは作らない。
- `make dev`（ビルドして起動）、`make test`（`swift test`）、`make app`（.app を作る）を用意する。Info.plist はスクリプトで書き出し、`LSUIElement` を true にして Dock に出さない。
- App Sandbox は使わない。`~/.claude` を読み、`claude` を子プロセスで起動するため。
- UI の文言は日本語と英語。設定で選び、未設定なら日本語。カードの用語と定義は claude が書いたまま訳さない。

## 取り込み

### 読む範囲

- `~/.claude/history.jsonl` のうち、`timestamp` が `importedThrough` より新しい行を読む。
- LLM に渡す前にコードで落とすもの：`/btw` と `/term` 以外のスラッシュコマンド、500字を超える行、壊れた行、`sessionId` のない行（どの行にもある欄なので、欠けていれば壊れた行と同じに扱う。2026-09-23 に10010行を数えると0件だった）。
- 初回は直近30日分だけを読む。それより古いセッション記録は消えていて（`cleanupPeriodDays` の既定値が30日）、定義のもとになる会話がないため。

### ① 判定（Sonnet、200件ずつ）

- 番号と本文の一覧を渡し、言葉や略語や概念の意味を聞いている行だけを `{id, term}` で返してもらう。
- 意味は分かっていて原因ややり方を聞いている質問（例：「LCP が悪いのはなぜ？」）は外す。
- そのプロジェクトの中でしか通じない呼び名も外す：人の略称やあだ名、マイルストーンや段階の番号、特定のファイル、文書、関数、変数、画面部品の名前。2026-09-23 の初回同期で、29枚中6〜10枚がこの種の呼び名だったため。
- `/term <用語>` の行は判定を飛ばし、引数をそのまま用語として扱う。

### 会話の切り出し（LLM なし）

①で用語が分かった後に行う。

- `history.jsonl` の `sessionId` から `~/.claude/projects/*/<sessionId>.jsonl` を開く。
- セッション記録の `type: "user"` の行には、人の入力のほかにツールの実行結果（`tool_result`）も入っている。2026-09-23 に1つのセッションで数えると、user の行のうち323件がツールの実行結果で、人が打った入力は `promptSource: "typed"` の約100件だった。
  - 人の入力：`type: "user"`、`isSidechain` が false で、次のどちらかに当てはまる行。
    - `promptSource` が `"typed"` か `"queued"`（Claude の作業中に打って待たされた入力）
    - `promptSource` がなく、本文が `<command-message>` で始まる（`/term` などのスラッシュコマンド）。2026-09-23 に `/term foo-rate` で確かめた。直後に入るスキル本文の user 行（「Base directory for this skill: …」）は人の入力ではないので使わない。
  - Claude の回答：`type: "assistant"` の行のうち、`message.content` の `text` の部分だけ。`thinking` と `tool_use` は捨てる。
- 時刻の形式が違う。`history.jsonl` はミリ秒の数値、セッション記録は ISO 8601 の文字列。人の入力のうち、時刻の差が5秒以内で最も近いものをその質問の位置とみなす。見つからなければ会話なしで扱う。
  - 2026-09-23 に普段のプロンプト60件で測ると、51件が1秒以内に見つかった（セッション記録の方が5〜762ミリ秒あと）。本文では突き合わせない。貼り付けたテキストが `history.jsonl` では `[Pasted text #1]` に置き換わっていて一致しないため。
  - 時刻の差に上限を付けないと、別のプロンプトに当たることがある（同じ60件で、数十秒から数分ずれた別の入力が最も近くなる例があった）。
- `/btw` は回答がどこにも保存されない（`/btw` はツールを使えず、回答は画面の小窓に出るだけ）。そこで、質問の時刻より前の人の入力と回答を後ろからさかのぼり、用語（大文字小文字を区別しない）を含む最も近い行を探して、その前後を上限6000字まで切り出す。見つからなければ、直前の人の入力と回答を上限6000字まで切り出す。
  - 直前のやり取りだけでは足りない例：「TF change とは？」の149秒前のやり取りに TF は出てこず、出てくるのは275秒前の回答だった。
- 普段のプロンプトと `/term` は、その質問から次の人の入力までにある回答の `text` を上限6000字まで切り出す。カードの定義は、利用者が実際に読んだ回答をもとにする。
- セッション記録が見つからなければ、質問文だけを渡す。

### ② カード作成（Sonnet、10件ずつ）

- 渡すもの：質問文、①で分かった用語、切り出した会話、今あるタグの一覧。1つの質問で用語を2つ聞いていると、同じ質問が2件並ぶので、①の用語でどちらの項目かを区別してもらう。タグの一覧を渡すのは、既存のタグを使い回してもらうため。誤答は同じタグのカードから選ぶので、タグがばらけると誤答選びが効かない。
- 返してもらうもの：`term`、設定の言語で書いた `definition`（日本語は60字以内、英語は120字以内）、`tags`（1〜2個）、`distractors`（同じ分野のそれらしい誤った定義を3つ。スキーマの `minItems` で3つ未満を返せないようにしている。4択にならないカードを作らないため。長さは `definition` との差を10字以内（英語は20字以内）で、少なくとも1つは `definition` より長く）、`skip`。
  - 英語の字数を倍にしているのは、英字の幅がおよそ半分で、小窓での選択肢の大きさをそろえるため。2026-09-24 の試しの呼び出しでは、英語の定義は107字と114字になった。日本語のときの指示文は変えていない。
  - 最初は120字以内にしていた。2026-09-23 の初回同期で定義が中央値76字、誤答が中央値49字になり、4択の小窓に収まらないうえ、いちばん長い選択肢を選べば正解できてしまったため縮めた。
  - 60字にした後も、20枚中16枚で正解がいちばん長かった（誤答を毎回少しだけ短く作るため）。そこで誤答の少なくとも1つを定義より長くするよう頼んでいる。
  - 同じ20枚を AI 臭さの点で見直し、次も頼むことにした。定義を「〜ではない」の否定から始めない（正解だけが別の選択肢を打ち消す形になり、答えが割れる）。並べるときは「・」でなく「と」「や」でつなぐ。誤答に用語の一般的な意味を入れない（「ハードコード」で、会話での意味が正解なのに、一般的な意味が誤答に入っていた）。句点の有無と文末の言い方を正解と誤答でそろえる（途中に「。」があるのが正解だけのカードが2枚あった）。
- 会話がなく意味が1つに決まらない場合は `skip: true` を返してもらい、カードを作らない。当て推量の定義を覚えるよりは、カードがない方がよい。

### claude -p の呼び方

2026-09-23 に試して動いた形：

```sh
CLAUDE_CODE_SKIP_PROMPT_HISTORY=1 claude -p \
  --no-session-persistence \
  --settings '{"disableAllHooks": true}' \
  --strict-mcp-config --mcp-config '{"mcpServers":{}}' \
  --tools "" \
  --model sonnet \
  --output-format json --json-schema '<schema>' \
  "<prompt>" < /dev/null
```

- 作業フォルダは `~/Library/Application Support/Recordo/claude-cwd/`（空のフォルダ）にする。プロジェクトの `.mcp.json` や CLAUDE.md を読ませないため。
- 結果は JSON の `structured_output` から読む。`is_error` が true なら失敗として扱う。
- `CLAUDE_CODE_SKIP_PROMPT_HISTORY=1` と `--no-session-persistence` を必ず付ける。付けないと、Recordo が送った判定用のプロンプトが `history.jsonl` に入り、次の同期で自分自身を取り込む。
- `--bare` は使えない。ログイン情報を読まないため「Not logged in」で失敗する。
- MCP とツールを外すと、前置きは約1.1万トークン、応答は約2.5秒だった（haiku で計測）。`--model sonnet` でも `structured_output` が返ることを確かめた。
- `claude` の場所：Finder から起動したアプリには nvm のパスが通らない。起動時に `/bin/zsh -lic 'command -v claude'` を実行し、出力の最後の行を使う（`-lc` では見つからなかった）。見つからなければ設定で指定してもらう。

### 保存と重複

- ②が返した `term` をそろえた形（`key`）にして、既存のカードと比べる。そろえ方：小文字にする、前後の空白を取る、連続する空白を1つにする、末尾の「とは」「って何」「?」「？」を外す。
- すでにカードがある用語なら、新しいカードは作らない。そのカードの `asked` に履歴を足し、段0に戻す。聞き直したのは忘れていたからなので、間隔を最初からやり直す。
- 200件の塊ごとに、①と②が両方成功したらカードを保存し、`importedThrough` をその塊の最後の時刻まで進める。

### いつ同期するか

- 60秒ごとのチェックで、`lastSyncAt` から24時間たっていれば同期する。専用のタイマーは作らない。
- 同期に失敗したら、1時間は同期し直さない。ログインが切れたままの claude を60秒ごとに呼び続けないため。失敗した時刻はメモリにだけ持つので、アプリを起動し直すと待ちは消える。
- メニューの「今すぐ同期」でも同じ処理を呼ぶ。同期中はボタンを押せなくし、自動と手動が同時に走らないようにする。
- 同期中はメニューに「同期中 3/15」のように塊の進み具合を出す。

## /term

- リポジトリの `skills/term/SKILL.md` に置き、`make install-skill` で `~/.claude/skills/term` からリンクする。中身は「引数の用語を、今の会話の文脈に沿って短く説明する」だけ。ファイルは書き出さない。
- 回答が本筋の会話に入るのは承知の上。判定が取りこぼしたときの保険として、確実に残したいときだけ使う。

## 出題

### いつ出すか

60秒ごとのチェックで、次をすべて満たしたら出す。

- `lastShownAt` から出題の間隔（既定3時間）がたっている
- 期限（`due`）の来たカードがある
- 集中モードではない
- 静かな時間帯ではない
- 手前のアプリが全画面ではない
- 小窓をすでに表示していない

集中モードは `~/Library/DoNotDisturb/DB/Assertions.json` の `.data[0].storeAssertionRecords[0]` があるかで判定する。手動かタイマーでオンにした集中モードしか記録されないので、スケジュールでオンになる分は静かな時間帯の設定で補う。全画面の判定は `frontmostIsFullScreen()` で、最前面のアプリに画面と同じ大きさのウィンドウがあるかを見る。

メニューの「今すぐ出題」は、間隔と止める条件を無視して出す。ただし、同期と出題は同時に動かさない。同期中は「今すぐ出題」を押せず、小窓を出している間は同期を始めない。同期は始めに読んだカードを持ったまま塊ごとに保存するので、同期中に答えた結果は上書きされて消えるため。

### 1回の出題

- 最大3問。`due` の古い順に出し、残りは次の回に回す。
- 問題は用語、選択肢は A〜D の4つの定義。
- 誤答の選び方：同じタグを持つ他のカードの定義から選び、足りない分はそのカードの `distractors` で埋める。正解と同じ `key` のカードは使わない。4つの順番は毎回混ぜる。
- 答える前のボタン：
  - 「分からない」は不正解として扱う。当てずっぽうで25%当たると、覚えていないカードの間隔が延びてしまうため。
  - 「後で」は小窓を閉じるだけ。カードは期限切れのまま残り、次の回に出る。答えた後は ✕ で閉じられるので、「後で」は答える前だけ置く。
- 答えた後：
  - 選択肢に ✓ と ✗ を付ける。正誤を色だけで伝えない。正しい定義は ✓ の行で示し、答え合わせでもう一度は出さない。
  - 正誤（「正解」「不正解」「正しい答えは B」）と、いつどこで聞いたか（例：「9/20 · recordo · /btw で質問」）は、下端の固定の欄に1行で出す。定義が長いと本文は小窓の上限まで伸びるので、選択肢の下に置くと見えなくなるため。
  - 自動では進まない。「次へ」（Space キー）を押すまで待つ。最後の問題では「閉じる」になる。
  - キー操作（A〜D、Space、Esc）は、小窓をクリックしてキーウィンドウにした後に効く。出た直後は作業中のアプリからキー入力を奪わないため。
  - 下端の左に「このカードを捨てる」を置く。LLM が作った定義が間違っていたときのため。押すと「捨てました 元に戻す」に替わり、実際に消すのは次へ進むか閉じたとき。確認のダイアログは出さない。
- 期限の来たカードがないときに「今すぐ出題」を押したら、空の小窓を出さず、理由（カードがない、期限の来たカードがない、cards.json を読めない）を出す。主ボタン（「閉じる」か「今すぐ同期」）は出題と同じく Space で押せる。

## データの形

`~/Library/Application Support/Recordo/cards.json`。開発ビルド（`Bundle.main.bundleIdentifier == nil`）は `dev-cards.json` を使う。

```json
{
  "version": 1,
  "importedThrough": 1790154000000,
  "lastSyncAt": "2026-09-23T09:00:00Z",
  "lastShownAt": "2026-09-23T08:00:00Z",
  "cards": [{
    "id": "UUID",
    "term": "immutable",
    "key": "immutable",
    "definition": "作成した後に中身を変更できないこと。…",
    "tags": ["プログラミング"],
    "distractors": ["…", "…", "…"],
    "box": 2,
    "due": "2026-09-26T08:00:00Z",
    "asked": [{ "at": "…", "project": "recordo", "via": "btw" }],
    "reviews": [{ "at": "…", "correct": true }]
  }]
}
```

- `via` は `btw`、`term`、`prompt` のどれか。
- `asked` は聞いた履歴を全部残す。何度も聞き直している用語が分かる。
- `reviews` は答えた履歴を全部残す。「答え続けているか」をこれで数える。
- 書き込みは `Data.write(to:options: .atomic)`。途中で落ちても半端なファイルが残らない。
- 読み込みに失敗したら上書きしない。空のデータで保存し直すと全カードが消えるため。メニューに「cards.json を読めませんでした」と出し、取り込みも出題も止める。
- 全部読んで全部書く。カードは1年で数百枚の見込みなので、これで足りる。

## 設定

`UserDefaults` に置き、設定ウィンドウ（SwiftUI の `Settings`）で変える。ウィンドウは、左のサイドバーで画面を選び、右にカードで項目を並べる（2026-09-23 にユーザーの指示で、1枚のフォームから変えた）。

- 一般
  - 言語（システムに合わせる、日本語、English。既定は日本語）。画面の文言だけが切り替わり、開いている設定ウィンドウとメニューはその場で替わる。出ている小窓は次に出すときから。
  - 外観（システム、ライト、ダーク。既定はシステム）。`NSApp.appearance` を切り替えるので、小窓とその背景のぼかし、設定ウィンドウがその場で替わる。
- 出題
  - 出題の間隔（既定3時間）
  - 静かな時間帯（開始と終了の時刻。既定はなし）
  - 集中モード：`Assertions.json` を読めるかを2秒おきに確かめて出す。読めなければ「フルディスクアクセスが必要です」と、フルディスクアクセスの画面を開くボタンを出す。
- 同期
  - `claude` の場所（空なら起動時に自動で探す）と、見つかった場所
  - 最後の同期

## 失敗したとき

| 起きたこと | 挙動 |
|---|---|
| `claude` が見つからない | 同期を止め、メニューに「claude が見つかりません。設定で場所を指定してください」 |
| ログインが切れている（`is_error` かつ「Not logged in」） | 同期を止め、メニューに「claude にログインしてください」 |
| 応答が読めない、`is_error` | その塊で止める。`importedThrough` は進めない |
| `history.jsonl` の行が壊れている | その行だけ飛ばす |
| セッション記録がない | 質問文だけで②に回す（②が `skip` を返せばカードは作らない） |
| `cards.json` が読めない | 上書きせず、取り込みと出題を止める |

同期が途中で止まっても `importedThrough` を進めないので、次の同期は同じところからやり直す。取りこぼしも重複も起きない。

## 画面の作り方

Swift を書く前に HTML の試作を作り、承認をもらう。

- `apple-design` スキルを読み込んでから作る。
- 土台は `design/sessions/quiz/` の試作と、`QuizStyle.swift` の値（文字サイズ、色、角丸、動き）。
- 置き場所は `design/sessions/<画面>/`。
- 対象の画面：出題の小窓（出題中、正解、不正解、出題するカードがない）、メニュー（通常、同期中、同期失敗）、設定ウィンドウ。
- 確かめる状態：ライトとダーク、文字サイズ200%、「視差効果を減らす」オン。

試作（`design/sessions/quiz/`）は 2026-09-23 に承認された。メニューは SwiftUI の `MenuBarExtra(.menu)`、つまり macOS 標準のメニューなので、試作と次の3点が違う。

- 「期限 5 枚」は右寄せにできないので、「今すぐ出題（期限 5 枚）」とラベルに入れる
- 同期中の回るマークは出せないので、「同期中 3/11」の文字だけにする
- メニューが開く動きは OS の標準のまま

英語の文言と、設定の「言語」と「外観」の行は、試作を作らずに Swift で足した。並びと部品は日本語と同じで、英語の出題の小窓も 340pt の幅で下端が1行に収まることを画面で確かめた。

以前作った別のアプリの `QuizPanel`（`NSPanel`、`.nonactivatingPanel`、`level = .floating`、右下24pt、`orderFrontRegardless()`）はほぼそのまま移す。

## テスト

XCTest で書く。

- Leitner：段と正誤から次の `due` と段を返す関数を、表のとおりに確かめる。
- 用語のそろえ方と重複：聞き直した用語が段0に戻り、カードが増えないこと。
- 誤答の選び方：同じタグを優先し、足りない分を `distractors` で埋め、正解と同じ `key` を選ばないこと。
- `history.jsonl` の読み込み：`importedThrough` より古い行、落とすべきスラッシュコマンド、500字超、壊れた行、`sessionId` のない行。
- 会話の切り出し：小さなセッション記録のフィクスチャで確かめる。フィクスチャには、ツールの実行結果の user 行、`thinking` と `tool_use` の assistant 行、用語が直前ではなく2つ前のやり取りに出てくる `/btw` を入れる。
  - `/btw` では、用語を含む行の前後が切り出されること
  - 普段のプロンプトでは、続く回答の `text` だけが切り出され、ツールの実行結果が混ざらないこと
- Importer：偽の `ClaudeRunner` で、成功したら `importedThrough` が進み、失敗したら進まないこと。塊に分けること。
- 本物の `claude -p` を呼ぶテストは `CLAUDE_LIVE=1` のときだけ動かし、それ以外は `XCTSkip` にする。
- 画面は、テストとは別に実際に起動して目で確かめる。

## 手本にした既存のアプリ

以前作った別の macOS アプリから持ってくるもの：

- SwiftPM の作り（ライブラリ、数行の実行ファイル、テスト）と Makefile の形
- `QuizPanel` と `QuizStyle` の部品と値
- `QuizController` の「60秒ごとに起きて、時間が来たら出す」作り、静かな時間帯、全画面の判定

- `CLAUDE_LIVE=1` のような環境変数で本物の呼び出しのテストを分ける方法
- コメントは英語で2行まで、理由だけを書く決まりと、カーソルの決まり

変えるところ：

- 保存は SQLite ではなく JSON ファイル1つ。カードが数百枚なので、データベースほどの仕組みは要らない。
- 復習の間隔は FSRS ではなく Leitner。数時間おきの出題に刻みが合う。
- メニューバーは `NSStatusItem` ではなく `MenuBarExtra`。Recordo にはメインのウィンドウがないので、Dock 表示の切り替えは要らない。
- LLM は `claude -p` を子プロセスで呼ぶ。手本がないので新しく書く。
- 多言語対応は、String Catalog と `Bundle.module` を使わず、コードの中に日本語と英語を並べる（`tr("日本語", "English")`）。文言が60個ほどで、String Catalog にすると `Package.swift` にリソースを足し、.app を `xcodebuild` で作る必要が出るため。言語はシステム、日本語、English から選び、既定は日本語にした。

## 実装時に確かめること

- 集中モード中に、自動の出題が通しで止まるか。部品ごとには確かめた（下の「確かめ終わったこと」）が、自動の出題が来る時刻に集中モードをオンにして見たことはまだない。
- メニューを実際にクリックしたとき、設定ウィンドウが手前に開くか。AX で押したときは、本物のクリックを伴わないので手前に来なかった。

確かめ終わったこと（2026-09-23）：

- `~/Library/DoNotDisturb/DB/Assertions.json` は、Finder や `open` で起動したアプリからは読めなかった（`Operation not permitted`）。読めたのは、フルディスクアクセスを持つターミナルから起動したときだけ。判定を外す案もあったが、Recordo.app にフルディスクアクセスを与えることにした。与えると、Recordo が子プロセスで動かす `claude -p` にもその権限が及ぶ（ツールは `--tools ""` で外してある）。許可した後は、設定の「出題」の集中モードの行が「集中モード中は出しません」に替わった。おやすみモードをオンにすると、このファイルに記録が1件入ることも確かめた。
- 作り直してもフルディスクアクセスの許可は残る。`make install` の後も、`Info.plist` を変えて cdhash の違う版を同じ証明書で署名し直した後も、集中モードの行は緑のままだった。許可は中身のハッシュではなく、署名の証明書と `app.recordo` に結び付いているため。

- `/bin/zsh -lic` の出力の最後の行で、`claude` の場所が取れた（設定ウィンドウに `~/.nvm/…/claude` と出た）。
- 開発用の実行ファイルは、起動時に `NSApp.setActivationPolicy(.accessory)` を呼ぶので Dock に出ない。Info.plist の埋め込みは要らなかった。
- `MenuBarExtra` のメニューの中から `@Environment(\.openSettings)` で設定ウィンドウを開ける。
- 小窓は `NSHostingView.sizingOptions = []` と `quizSurface` の測り方で、内容の高さに合う。
- 非アクティブな `NSPanel` の中でも、キーウィンドウになれば `.keyboardShortcut`（A〜D、Space、Esc）が効く。`NSEvent` のモニターは要らなかった。
- 全画面の判定は、Preview を全画面にすると true、ウィンドウに戻すと false になった。
